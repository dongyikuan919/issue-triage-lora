# 故障分诊微调实验：阶段路线图

当前状态：初始化完成，开发尚未开始。以下任务均为计划。

整体路线：文档问答 → 工具助手 → 小模型微调实验。三个项目分别交付，按验收推进。

| 周 | 要学什么 | 当周可检查的产出 |
| --- | --- | --- |
| 13 | PyTorch 张量、梯度、交叉熵；SFT、LoRA 与 RAG 的分工 | 使用候选小模型完成未微调推理基线；写清训练输入、分类标签、预期 JSON 字段和预算 |
| 14 | 数据标注、去重、训练/验证/测试划分 | 在前两阶段持续积累的基础上，争取整理 200～500 条人工审核样本；按问题来源分组划分数据；先冻结至少 40 条独立测试案例 |
| 15 | Tokenizer、聊天模板、训练损失与 LoRA 参数 | 先用少量样本跑通训练、保存和重新加载；再做一次完整的小规模训练，保留模型版本与环境 |
| 16 | 过拟合、验证集选参、分类与字段提取指标 | 使用验证集比较参数与错误案例；比较规则基线、同一小模型的提示基线和微调模型，保持输入与约束一致 |
| 17 | 推理集成、失败回退、最终独立测试 | 将微调模型作为项目二的可选分诊组件；在冻结测试集上记录分类 Macro-F1、字段匹配、JSON 合法率、延迟和硬件 |
| 18 | 实验可复现性、模型与数据说明、开源发布 | 项目三 v0.1：训练/评测命令、配置、数据说明、对比报告；串起三项目演示，并明确推荐使用哪种方案 |

## 首版交付要求

- README 中说明实际可用的功能、运行步骤和限制。
- 提供可公开的示例输入与输出。
- 保留评测用例、结果和失败案例。
- 普通自动检查使用离线样例；在线模型评测单独运行，避免自动消耗 API 配额。
- 在干净环境中复核运行步骤后再发布 v0.1。

数据规模是初始准备目标，不代表足够或必然提升。测试集不参与提示选择和参数调整；微调没有优势时，记录结论并保留更简单的基线。
