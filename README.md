# issue-triage-lora · 客服意图与工单微调

用可复现的 LoRA 实验验证小模型在客服意图分类和工单字段提取上的价值，为客服流程提供可选的分流组件。

本项目属于「企业智能客服」开源学习路线：知识库问答 → 客服工具工作流 → 专项微调。首版建议聚焦一个企业软件（SaaS）产品，使用自写的虚构企业资料与模拟工单。

> 状态：仓库已初始化，业务功能尚未实现。以下是目标范围，不能视为已经可用的能力。

## 使用场景

输入一段客户会话 → 识别产品使用、账号访问、套餐服务等意图 → 提取输入中明确出现的产品和问题现象等字段；缺失信息标记为待补充。

## 首版计划

- 整理项目二的人工审核数据，保留来源与真实/合成标记。
- 按客户案例与会话分组去重，隔离训练、验证和冻结的独立测试集。
- 提供 LoRA 训练、保存、加载、推理和评测流程。
- 同条件比较规则、同一基础模型加提示、微调模型，报告意图 Macro-F1、字段匹配率和 JSON 合法率。
- 记录模型、环境、配置、延迟和成本；结果合格后作为项目二的可选客服分流组件。

## 项目衔接

使用项目二的审核数据，并附带可公开的虚构样例以独立复现实验。知识事实由项目一的知识库维护，专项微调聚焦意图与字段。

- [devdocs-rag](https://github.com/dongyikuan919/devdocs-rag)：企业知识库问答。
- [issue-triage-agent](https://github.com/dongyikuan919/issue-triage-agent)：智能客服工作台。
- [issue-triage-lora](https://github.com/dongyikuan919/issue-triage-lora)：客服意图与工单微调。

## 当前范围

只覆盖有限的客服意图与工单字段。标签定义、候选模型、训练预算和算力在进入实验阶段时确定；微调没有优势时，公开结果并保留更简单的基线。

## 数据与配置

仅提交自写或许可允许公开的样例。API 密钥、真实客服会话、客户标识和未经授权的企业资料不入库；配置方案确定后提供 `.env.example`。真实业务数据接入须先落实身份、权限与隐私处理。
